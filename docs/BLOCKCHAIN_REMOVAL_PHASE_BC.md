# Blockchain removal — Phases B and C contract (wallet identity and sign-in)

Parent: [BLOCKCHAIN_REMOVAL_PLAN.md](BLOCKCHAIN_REMOVAL_PLAN.md) (its "Rules for every agent" apply) and [ADR-0010](adr/0010-remove-blockchain-and-wallet-identity.md).
Source: a read-only survey of the code and live dev DB on 2026-09-29. Line numbers are as of commit `f7137e2`; re-grep before editing.

## Owner decisions (resolved — do not re-open)

- Patients: activation code at registration → the patient chooses a username and sets a password; optional TOTP; reset by an administrator in person.
- **PostgreSQL is required to sign in.** `X-User-Id`, `SignatureAuthMiddleware`, `REQUIRE_SIGNATURES` and the tokenless demo path are removed. In-memory storage remains for unit tests only.
- Keep the client-side `auth_proof` derivation so existing staff verifiers stay valid (no forced reset). Replace `@polkadot/util` helpers with `TextEncoder` + a hex helper.
- Staff accounts stay `pending` until an administrator activates them (existing behaviour).
- Class C (exact transaction authorization) keeps issuance/verification with TOTP-or-password; wiring it into mutations stays out of scope.
- `users.wallet_address` and the other wallet columns are dropped at the end of Phase C (M2), after the harnesses pass; a legacy mapping keeps sealed history resolvable.

Replaces staff/login.
POST /api/auth/register (Admin+B) {name, role, login_id, email?} → 201 {user_id, status:'pending', activation_required, credential_code, credential_expires_at}. Bootstrap {login_id, name, auth_proof, secret_key}.
POST /api/register creates Patient user + activation {code XXXX-XXXX-XXXX Crockford base32 60 bits, expires_at 72h}; POST /api/patients/{id}/activation-code re-issue (409 ALREADY_ACTIVATED). Keyed hash; 5 failures kill grant.
POST /api/auth/credentials/redeem {identifier, code, auth_proof, username?} → login body. 401 INVALID_GRANT, 409 USERNAME_TAKEN, 400 INVALID_USERNAME|INVALID_AUTH_PROOF, 429 GRANT_LOCKED. Username shares users_login_id_lower_key namespace.
POST /api/admin/users/{id}/credential-reset (Admin+B) → {credential_code, expires_at}, revoke all sessions. POST /api/admin/users/{id}/mfa-reset.
POST /api/auth/credentials/change {current_auth_proof, new_auth_proof}; revokes other sessions.
TOTP /api/auth/mfa/* keyed by user id; mfa/challenge also record_step_up('totp'); last_used_step replay guard.
Class C: /api/auth/transaction/challenge → {challenge_id, expires_in_secs, required_factor totp|password}; POST /api/auth/transaction/verify {challenge_id, code|auth_proof}. Remove session.step_up + /api/auth/step-up/*.
Remove X-User-Id + SignatureAuthMiddleware + REQUIRE_SIGNATURES. Quick Login via /api/auth/demo-credentials (demo.rs:375; drop keystore predicate). Memory-only mode cannot authenticate (auth_sessions needs pool).
